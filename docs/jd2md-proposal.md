# JD2MD 簡單版產品方案

定案：JC（@JonChenJC），2026-11-19。對應 [#2](https://github.com/ai4biz-tw/jd-ai-usercase/issues/2)。Daniel 10/14 建議稿裡的模組判準與 Markdown 格式我採用；簡單版不先等 server 與模型預算，改以靜態頁交付。

## 問題

職缺貼進 AI，回來的多半是空泛建議，不然就是把每一條職責貼上 AUTO／AUG／HUMAN。後者是官網 `/jd2md` 的做法，我在 9/30 否決了：逐條貼標籤交不出能用的東西。本 repo 的 `index.html` 是另一條路（七個固定 use case 模板比關鍵字）。[#1](https://github.com/ai4biz-tw/jd-ai-usercase/issues/1) 實測會配錯，護理師被配成管理報告、業務的「開發新客戶」被配成工程。兩條路都沒有把同一件事收成一份可交接的工作。

## 給誰用

想把職缺裡某一塊工作先交給 AI 的在職者，以及要幫客戶看「這份 JD 哪幾塊可以先交」的顧問。讀者帶走的不是分析報告，是能貼進 Claude／ChatGPT 的交接文件。

## 決定

一份 JD 產出 **1–6 份 Markdown**，每份是一個工作模組，另加一份「仍然需要你本人」。一個模組要同時有觸發、產出、拿得到的輸入、以及驗收方式。維繫關係、跨部門溝通這種沒有單獨產出的，不硬做成模組。

可取代程度以**模組**為單位，三選一：AUTO（可直接交）、AUG（人機一起做）、HUMAN-LEAD（人主導）。不逐條貼標籤。

## 簡單版範圍

| | 現在這版 `jd2md.html` | 明確不做 |
|---|---|---|
| 輸入 | 貼全文為主。連結會試抓；CORS、登入牆或空頁就停，請改貼全文 | 代抓要登入的頁面、爬 104 |
| 產出 | 模組 MD。可逐份複製、整包複製、下載一個 `.md` 或一個 `.zip` | 線上編輯、帳號、雲端存檔 |
| 做法 | 瀏覽器內把相關職責收成模組，再填下面的格式。不送出、不保存 | 金鑰放前端、多 agent |
| 對不上 | 留下原文與原因，**不補**無關模板 | 為了湊滿三份而硬配 |
| 語言 | 繁中、英文 JD 都收，輸出繁中 | 英文介面、簡體介面 |
| 對外 | 不發官號。`index.html` 維持 use case 工具，不把它叫做 JD2MD | 產品完成前的社群發文 |

句型歸併做得到「報價單＋訂單＋收款 → 報價到收款」，做不到讀出 JD 沒寫明的工作。輸入清單是該類模組的建議，不是從 JD 推斷的事實；事實只來自引用的原文。這是有意的取捨：先讓格式可看、可複製。

## 每份 MD

1. 模組名稱
2. 這個模組在做什麼（觸發 → 產出，並引用 JD 原文）
3. 可取代程度與一句理由
4. 輸入
5. 步驟（每步標明 AI 做／人核准／人做）
6. 交付物與驗收
7. 風險與人工把關
8. 給 AI 的指令（可直接貼）

章節結構借 agency-agents 的固定寫法，不導入該套件，也不摘錄其內文。見 `docs/agency-agents-eval.md`。

## 風險

| 風險 | 這版怎麼接 |
|---|---|
| 句型會漏、會分錯桶 | 頁面標明是草稿；每份都引用原文。分錯比硬湊模板看得懂 |
| 連結常常抓不到 | 全文就是主路徑，失敗要寫原因 |
| 下一版才用得到模型 | 金鑰不能放 GitHub Pages。模型、誰付錢、每日上限由 DT 與我拍板後才加 API。簡單版單次 12,000 字；接上 API 後收到 8,000 |
| 使用者貼進內部資料 | 這版資料不出瀏覽器。接上 API 後頁面要寫「不儲存，只送去產生一次」 |
| 還沒有標註集 | 接模型之前，先用 10 份真實 JD 對「應該切出哪些模組」 |

## 下一步

1. 用這頁與 `jd2md.html` 在週會看簡單版。官號先不發。
2. 財務、業務、護理三份 JD 若還配錯，加句型，不加模板。
3. 模型費用與每日上限拍板後，才做會呼叫模型的完整版。
