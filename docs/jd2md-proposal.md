# JD2MD 簡單版：建議稿（給 JC 提案參考）

> 對應 ai4biz-tw/jd-ai-usercase#2（簡單版產品方案）、ai4biz-tw/jd-ai-usercase#3（設計方向：一份 JD → 多個可被取代的 MD）。
> 2026-10-14 Opus-5.5 起草。**這是建議稿，產品方案由 @JonChenJC 定案**；這裡只把 #3 的方向展開成能直接做 demo 的規格，並標出技術卡點。

## 1. 一句話

貼一份 JD，拿到 **3–6 份 Markdown**，每份是一個「AI 可以整塊接手的工作模組」的交接文件——讀者拿去就能丟進 Claude／ChatGPT 當 system prompt 或 skill 用。

## 2. 為什麼不能沿用現在的做法

| 現況 | 問題 |
|---|---|
| ai4biz.tw/jd2md：每條 bullet 用關鍵字分 AUTO／AUG／HUMAN | JC 9/30 說這不是要的設計；逐條貼標籤不會產出可用的東西 |
| jd-ai-usercase 頁：7 個固定模板＋關鍵字比對 | review 實測：護理師 JD 被配成「管理報告與差異分析」、業務 JD 被配成「預算規劃」（見 ai4biz-tw/jd-ai-usercase#1） |

兩者共同的根：**沒有理解 JD，只是在比字**。「模組」需要把散落在不同 bullet 的同一件事合起來（例如「撰寫報價單」＋「追蹤訂單與收款」＝一個「報價到收款」模組），這一步關鍵字做不到，要用 LLM。

## 3. 「模組」的定義（建議給 demo 用的判準）

一個模組＝滿足以下四點的一段工作：

1. **有明確觸發**：什麼事件或時間點會開始（收到詢價、每週一、月結日）
2. **有明確產出**：交出去的是一個東西（報價單、週報、對帳表）
3. **輸入可以拿得到**：做這件事要的資料，AI 在合理權限下拿得到
4. **可以被驗收**：有人能判斷這次做得對不對

不符合的（例如「維繫客戶關係」「跨部門溝通」）不硬做成模組，列在最後的「仍然需要你本人」清單，並寫原因。

## 4. 每份 MD 的固定格式

```
# <模組名稱>（例：報價到收款）

## 這個模組在做什麼
一段話：觸發 → 產出，以及在原 JD 對應哪幾條（引用原文）

## 可取代程度
AUTO / AUG / HUMAN-LEAD 三選一，附一句理由

## 輸入
- 需要的資料、檔案、系統

## 步驟
1. ...（每步標明 AI 做／人做／人核准）

## 交付物與驗收
- 產出長什麼樣、怎樣算做對

## 風險與人工把關
- 什麼情況必須停下來給人

## 給 AI 的指令（可直接貼）
（一段 system prompt，讀者複製貼上就能用）
```

最後一節是產品的「hook」：讀者拿到的不是分析報告，而是能立刻用的東西。

## 5. 簡單版 demo 的範圍（建議）

| 項目 | 簡單版做 | 先不做 |
|---|---|---|
| 輸入 | 貼 JD 全文（連結抓取在純前端幾乎都被 CORS 擋，見 #1 review） | 貼連結自動抓 |
| 產出 | 3–6 份 MD＋一份「仍需要你本人」清單；可逐份複製、全部下載 zip | 線上編輯、存檔 |
| 模型 | 一次 LLM 呼叫，結構化輸出（JSON → 前端排成 MD） | 多 agent 分工 |
| 語言 | 繁中 JD、英文 JD 都吃，輸出繁中 | 輸出英文 |
| 範例 | 3 份預跑好的 JD（財務分析師、業務專員、護理師）直接展示，不花 token | |

## 6. 技術卡點（給 DT 確認可行性）

| 卡點 | 說明 | 建議 |
|---|---|---|
| 需要 server 端 | LLM 金鑰不能放前端；現在 jd-ai-usercase 是 GitHub Pages 純靜態 | 放到 ai4biz-web 底下做一支 API route（ai4biz.tw/jd2md 已經 rewrite 過來），或另開 Vercel 專案 |
| 用哪個模型、誰付錢 | 一份 JD 約 1–2k token 輸入、4–6k token 輸出 | 先用便宜模型；每日呼叫上限＋單 IP 限流，到上限就只顯示預跑範例 |
| 濫用 | 公開 API 會被拿去當免費 LLM | 輸入長度上限（例如 8,000 字）、origin 檢查、限流（ai4biz-web `/api/subscribe` 已有現成寫法） |
| 品質驗收 | 怎麼判斷模組切得好不好 | 10 份真實 JD 人工標註「應該切出哪些模組」，demo 版要命中 ≥70% |
| 個資 | JD 本身不是個資，但使用者可能貼進公司內部資訊 | 頁面寫明「不儲存、只送去模型產生一次」 |

**結論：方向可行，沒有技術硬卡；真正要拍板的是「模型費用誰出、每日上限多少」。** 拍板後 demo 約 1–2 天工作量。

## 7. 和 agency-agents 的關係

ai4biz-tw/jd-ai-usercase#4 的評估結論是不導入、只借鏡；其中「每個專家 agent 都有固定章節（身分、任務、硬規則、交付物、流程、成功指標）」這個格式，正好可以當第 4 節 MD 格式的參考。詳見 `docs/agency-agents-eval.md`。
